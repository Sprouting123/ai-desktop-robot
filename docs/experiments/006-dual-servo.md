# 实验 006：双 SG90 舵机协同控制

- 日期：2026-11-07（Asia/Shanghai）。
- 状态：**已验收（2026-11-07）。** 舵机 1、舵机 2 单独测试和双舵机同时运动均已获用户确认；运动中 `servo both stop` 因动作过快未能人工复现，仅有软件检查证据，边界见第 8 节。第二阶段未开始。
- 基线：实验 005 的单舵机控制、实验 004 的十种 OLED 表情与眨眼均已验收，历史记录不修改。
- 目标：在保留全部旧命令的前提下，让两只 SG90 各自独立控制，并为后续同步动作和动作序列预留接口。本次只实施第一阶段，第二阶段在实物验收后另开。

## 1. 范围与验收标准

第一阶段只做双舵机独立控制，不实现同步动作序列、表情联动、Wi-Fi 或语音。

软件验收：

- `diagnostics`、`rgb_gpio48`、`rgb_gpio38` 三个环境构建成功。
- GPIO48 固件烧录及区域 hash 校验成功。
- 两个 LEDC 通道分别初始化成功，上电都不输出脉冲。
- 旧命令 `servo center`、`servo <角度>`、`servo status`、`servo stop` 保持实验 005 的含义，仍指向舵机 1。
- 新增 `servo1 ...`、`servo2 ...`，分别独立控制两个通道。
- `servo both center`、`servo both stop` 同时作用于两只舵机。
- 两只舵机的角度、目标、运动状态和停止状态互不干扰；停止一只不影响另一只。
- 越界、非数字、负数和多余参数被拒绝，且不改变任何舵机状态。
- 运动仍按 20ms 步进渐进，OLED 眨眼和串口命令保持响应。
- 自动化测试和短时连续运行无失败、无复位、堆稳定。

实物验收（用户观察，分三步，每步等待用户确认）：

- 舵机 1：接线和运动与实验 005 一致，动作渐进、方向正确、无异常。
- 舵机 2：单独接 GPIO5 后运动正常，且舵机 1 保持不动。
- 双舵机：`servo both center`、`servo both stop` 和同时运动正常，互相不干扰。

## 2. 硬件、接线与安全

| 信号 | 连接 |
| --- | --- |
| 舵机 1 信号 | GPIO4，LEDC 通道 0 |
| 舵机 2 信号 | 暂定 GPIO5，LEDC 通道 1；用户报告，尚未实物接线验证 |
| 两只舵机电源 | 共用外部 5V 标称电源，红线接正极、棕线接负极 |
| 共地 | ESP32 GND ↔ 外部电源负极 |
| ESP32 供电 | USB（COM 口） |
| OLED | ESP32 3V3、GPIO8/9、0x3C、100kHz |
| RGB | GPIO48 |

- GPIO5 在 ESP32-S3 上不是启动 strapping 引脚，当前固件也未使用；Flash/PSRAM 使用模组内部 SPI 引脚，OLED 使用 GPIO8/9，RGB 使用 GPIO48，因此 GPIO5 在软件层面可用。
- 两只舵机由同一 5V 电源供电；标称 5A 电源在空载时测得 5.49V，但双舵机同时启动、堵转时的电流余量尚未测量。
- 首次测试不安装摇臂、不带机械负载；开发、烧录和自动串口测试期间保持外部 5V 断开。
- 禁止把外部 5V 接到 ESP32 3V3 或任何 GPIO；发现堵转、异常发热、持续抖动或线缆松动时立即断开外部 5V。

## 3. 设计与通道分配

两个独立 `servo::Controller` 实例共用同一份参数结构，参数来自 `src/servo_controller.h`：

| 参数 | 舵机 1 | 舵机 2 |
| --- | --- | --- |
| 信号引脚 | GPIO4 | GPIO5 |
| LEDC 通道 | 0 | 1 |
| 刷新频率 | 50Hz | 50Hz |
| 分辨率 | 14 位 | 14 位 |
| 软件限位 | 60–120° | 60–120° |
| 中位 | 90° | 90° |
| 脉宽范围 | 600–2400µs | 600–2400µs |
| 运动速度 | 60°/s，20ms 步进 | 60°/s，20ms 步进 |

ESP32-S3 的 LEDC 通道 0 和 1 共用定时器 0（Arduino-ESP32 2.0.17 的 `ledcSetup` 映射为 `timer = (channel / 2) % 4`）。本次两个通道都配置为 50Hz、14 位，因此共用定时器不会产生频率冲突；将来若某只舵机需要不同频率，应改用通道 2/3 等独立定时器。

每个实例自己保存 `currentTenths_`、`targetTenths_`、`moving_`、`outputEnabled_`、`lastStepMs_`，状态机与实验 005 相同：

- `stopped`：输出关闭，0 占空比，舵机放松；
- `idle`：输出开启并保持在当前角度；
- `moving`：每 20ms 向目标走一小步，到达后回到 `idle`。

`loop()` 依次调用两个实例的 `update()`，每次最多各走一步，不等待、不阻塞。

## 4. 串口接口

大小写不敏感，行尾支持 LF/CR/CRLF，仍受 32 字符缓冲和非法字符保护。

| 命令 | 行为 | 典型回复 |
| --- | --- | --- |
| `servo center` | 舵机 1 回中位（实验 005 兼容） | `OK servo=center angle=90` |
| `servo <60-120>` | 舵机 1 渐进到角度（实验 005 兼容） | `OK servo=target angle=75` |
| `servo status` | 查询舵机 1，输出 `SERVO ...` | `SERVO state=... channel=0` |
| `servo stop` | 停止舵机 1 并关闭其脉冲 | `OK servo=stopped output=off` |
| `servo1 center` / `<角度>` / `status` / `stop` | 显式控制舵机 1 | `OK servo1=...` / `SERVO1 ...` |
| `servo2 center` / `<角度>` / `status` / `stop` | 控制舵机 2 | `OK servo2=...` / `SERVO2 ...` |
| `servo both center` | 两只同时回中位 | 两行 `OK servo1=center ...`、`OK servo2=center ...` |
| `servo both stop` | 两只同时停止并关闭脉冲 | 两行 `OK servo1=stopped ...`、`OK servo2=stopped ...` |

状态行在实验 005 字段后增加了 `channel=`，例如：

```text
SERVO1 state=idle ready=1 angle=90 target=90 pulse_us=1500 output=on pin=4 frequency_hz=50 min=60 max=120 speed_dps=60 channel=0
SERVO2 state=stopped ready=1 angle=120 target=120 pulse_us=0 output=off pin=5 frequency_hz=50 min=60 max=120 speed_dps=60 channel=1
```

`servo both` 只接受 `center` 和 `stop`；`servo both 75`、`servo both`、`servo both wiggle`、`servo1 both center` 均返回 `ERR servo_usage; use help`。两条 `both` 命令先检查两个实例是否就绪，避免只执行一半。

## 7. 实物验收步骤（待用户执行，分三步）

当前设备运行实验 006 固件，两个舵机输出均关闭，RGB 熄灭，屏幕为 normal 眼睛；外部 5V 断开。舵机 2 的信号线尚未接到 GPIO5，实物验收前需要用户接线。

### 7.1 舵机 1

1. 保持外部 5V 断开，确认舵机 1 仍按实验 005 接在 GPIO4，ESP32 GND 与电源负极相连；不装摇臂。
2. 打开监视器，输入 `servo1 status`，应为 `stopped`、`output=off`、`angle=90`。
3. 外部 5V 上电，两只舵机都不应自动运动。
4. 输入 `servo1 center`、`servo1 75`、`servo1 105`、`servo1 center`，确认舵机 1 动作渐进、方向正常；同时确认舵机 2 不动。
5. 输入 `servo1 stop`，确认舵机 1 放松；再 `servo1 center` 可恢复。

**完成第 1 步后先反馈，再进入舵机 2 测试。** 2026-11-07 用户反馈舵机 1 步骤正常。

### 7.2 舵机 2

1. 断开外部 5V，把舵机 2 信号线接到 GPIO5，红线接外部 5V 正极、棕线接负极，保持共地；不装摇臂。
2. 上电后两只舵机都不应自动运动。
3. 输入 `servo2 center`、`servo2 75`、`servo2 105`、`servo2 center`，确认舵机 2 动作正常，同时舵机 1 保持不动。
4. 输入 `servo2 stop`，确认舵机 2 放松；再 `servo2 center` 可恢复。

**完成第 2 步后先反馈，再进入双舵机测试。** 2026-11-07 用户反馈舵机 2 单独测试正常。

### 7.3 双舵机

1. 输入 `servo both center`，两只都应回到中位。
2. 输入 `servo1 120` 和 `servo2 60`，确认两只按各自目标独立运动。
3. 在运动途中输入 `servo both stop`，两只都应停下并放松；再 `servo both center` 应同时恢复。
4. 观察运动时 OLED 眼睛是否继续眨眼，串口是否及时回复；连续动作后检查舵机与电源温度，明显烫手立即断电。

每步都需要用户确认后才能继续；自动化测试不能替代这些观察。完成后先 `servo both stop`，再关外部 5V。

2026-11-07 用户反馈双舵机同时运动正常，但运动中输入 `servo both stop` 无法测试：软件速度为 60°/s，60° 全行程约 1 秒，人工输入命令来不及在运动中发出。因此该命令的“运动中同时停止”只有自动化软件检查证据，未取得实物观察，见第 8 节。

## 8. 结果与边界

- 2026-11-07 用户已先后确认舵机 1 分步复验、舵机 2 单独测试和双舵机同时运动正常，`servo both center` 的实物效果也已确认，实验 006 第一阶段记为已验收。
- **运动中 `servo both stop` 未取得实物观察。** 60°/s 下 60° 全行程约 1 秒，人工串口输入无法在运动中赶上；自动化脚本的软件检查已确认两只同时中断、保留中间角度且 `pulse_us=0`，但这只是固件与串口证据，不等于实物截止效果。若以后需要实物确认，可先经用户同意降低速度或使用专门的分步脚本，届时重新记录。
- 双舵机同时动作的供电余量、电压跌落、堵转电流未测量；两只的平滑度、噪声、实际角度和发热只做了主观观察，未用仪器测量。
- 舵机 2 的 GPIO5 接线和供电尚未实物验证；`SERVO2_INIT ready=1` 只证明 LEDC 配置成功，不证明引脚输出或舵机运动。
- 两个通道共用 LEDC 定时器 0，当前配置完全相同，因此没有冲突；未来改变其中一只的频率或分辨率会影响另一只，需要重新分配通道。
- 角度、脉宽、状态机只证明固件按设计输出，不能证明舵机实际到达对应角度；本次没有角度标定、电流测量或带载测试。
- 第二阶段（同步动作序列、中途取消、紧急停止、表情联动接口）尚未开始。

## 9. 已解决问题

- **通道共用定时器**：Arduino-ESP32 2.0.17 中通道 0/1 共用定时器 0；两个实例都使用 50Hz、14 位，重复 `ledcSetup` 不会改变有效配置。已在文档中记录该约束。
- **旧命令兼容**：`servo ...` 保留为舵机 1 的别名，回复仍为 `OK servo=...`；新接口使用 `servo1`/`servo2` 前缀，避免改变实验 005 的行为。
- **测试时序误判**：`servo1 center` 从 75° 出发时需要约 0.25 秒才能到达 90°，测试最初立即断言 `idle` 而失败；改为等待运动结束后再检查。固件行为正确，修改的是测试。
- **同时停止命令的原子性**：`servo both center` 先检查两个实例都 ready，再执行；避免一个通道失败时只执行一半。

## 10. 尚未解决的问题

- 双舵机同时动作的电流、电压跌落和供电余量未测量；两只都已接线并通过单独的实物测试。
- 运动中 `servo both stop` 未取得实物观察；当前速度下人工无法在 1 秒内完成输入，只有软件检查证据。
- 600–2400µs 与 60–120° 是否需要按两只实物分别校准，尚未确定。
- 无位置反馈；`servo stop` 后手搬摇臂会使角度模型失效。
- 未测量双舵机同时启动/堵转电流，也未验证 5V 5A 电源在两只同时动作时的电压跌落。
- 第二阶段动作序列、紧急停止和表情联动尚未实现。

## 11. 学习要点

- **LEDC 通道与定时器**：通道号不等于定时器号；S3 上每两个通道共用一个定时器，同组通道必须使用相同频率和分辨率。
- **实例化控制器**：把角度、目标、状态都封装进 `Controller` 后，增加第二只舵机主要是新增一个实例和一组命令解析，不需要复制状态机。
- **向后兼容**：保留旧命令作为别名，比直接改旧命令更安全；新增显式 `servo1`/`servo2` 便于以后扩展。
- **独立调度**：两个 `update()` 各走一小步，OLED 仍按区域增量刷新，三者共享同一个 `loop()` 而不互相阻塞。
- **验证边界**：双通道初始化成功、PWM 数值正确和状态机独立，都不能证明舵机实际运动；实物验收必须分步进行。
