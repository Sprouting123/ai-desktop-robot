## 2. 硬件、接线与安全

用户报告的接线（尚未由本次实验逐项测量）：

| 信号 | 连接 |
| --- | --- |
| SG90 信号线 | GPIO4 |
| SG90 红线 | 外部 5V 电源正极 |
| SG90 棕线 | 外部 5V 电源负极 |
| 共地 | ESP32 GND ↔ 外部电源负极 |
| ESP32 供电 | USB（COM 口） |
| OLED | ESP32 3V3，GPIO8/9，0x3C，100kHz |

外部电源标称 5V 5A，空载实测 5.49V；本次不把它接到 ESP32 的 3V3 或任何 GPIO。

安全前提：

- 首次测试**不安装摇臂、不带机械负载**。
- 开发、烧录和本次软件测试期间保持舵机外部 5V 断开。
- 上电前再次核对红/棕/信号线和共地；不能把外部 5V 正极接到 ESP32 3V3 或 GPIO。
- 固件开机不输出脉冲，只有显式命令才使能 PWM。
- 发现堵转、异常发热、持续抖动或线缆松动时立即断开外部 5V。

建议顺序：USB 连接并烧录 → 外部 5V 仍断开 → 接线检查 → 打开监视器 → 外部 5V 上电 → 观察舵机不动 → 发送 `servo center` 开始首次运动。断电顺序为先 `servo stop`，再关外部 5V，最后拔 USB。

## 3. 设计与参数

参数集中在 `src/servo_controller.h` 的 `servo::Config`，以后校准只改这一处：

| 参数 | 当前值 | 说明 |
| --- | --- | --- |
| 信号引脚 | GPIO4 | 用户报告值；2026-11-07 实物运动证明该链路可用，未做电测量 |
| LEDC 通道 | 0 | 与 RGB 的 RMT、OLED 的 I²C 分开 |
| 刷新频率 | 50Hz | SG90 标准模拟舵机接口 |
| 占空比分辨率 | 14 位 | ESP32-S3 LEDC 最大 14 位；脉宽分辨率约 1.2µs |
| 脉宽范围 | 600–2400µs | 对应 0–180° 的保守全范围 |
| 软件角度范围 | 60–120° | 首次测试限制在机械中段，避免接近极限 |
| 中位 | 90° | 对应 1500µs |
| 运动速度 | 60°/s | 每 20ms 更新约 1.2° |
| 步进周期 | 20ms | 与 50Hz 刷新周期一致 |

角度到脉宽的线性映射为 `pulse_us = 600 + angle * 10`（0–180° 对应 600–2400µs）。因此 60°=1200µs、75°=1350µs、90°=1500µs、105°=1650µs、120°=1800µs。

控制状态：

- `stopped`：输出关闭，LEDC 占空比为 0，舵机没有脉冲、处于放松状态。
- `idle`：输出开启并保持当前角度。
- `moving`：按 20ms 周期逐步接近目标角度。

启动策略：`begin()` 只配置 LEDC 并把占空比写为 0，`current`/`target` 记为 90° 但**不输出脉冲**；因此上电不会自动扫动。首次 `servo center` 或角度命令才使能输出。停止后重新使能时，先按最后已知角度恢复输出，再从该角度渐进到新目标，避免突然跳回中位；如果停止期间用手搬动过摇臂，位置未知，应先 `servo center`。

`servo stop` 的安全策略：取消运动调度、把 LEDC 占空比写 0，保留最后已知角度和目标值供查询；舵机放松，不持续保持力矩。

## 4. 软件架构

```
src/
  main.cpp            串口解析、RGB、I²C、OLED 测试图/眼睛、舵机命令分发
  eyes_state.*        表情纯时间状态机
  eyes_render.*       表情纯绘图
  eyes_engine.*       表情调度与增量刷新
  servo_controller.*  单舵机 PWM、限位、渐进运动与停止策略
```

`servo::Controller` 接收一个 `Config`，不依赖 OLED 或串口输出格式。未来增加第二只舵机时，可以创建另一个 `Controller` 实例并使用不同 LEDC 通道/引脚；情绪动作层只需调用 `setAngle()`，不需要改 PWM 细节。

`loop()` 的顺序是：读取串口 → `eyesEngine.update()` → `servoController.update()`。舵机每 20ms 最多走一小步，不等待、不 `delay()`；OLED 每轮最多传输一个 32 字节区域，两者共享主循环。

## 5. 串口接口

新增命令（大小写不敏感，仍受 32 字符、CR/LF/CRLF 和非法字符保护）：

| 命令 | 行为 | 典型回复 |
| --- | --- | --- |
| `servo center` | 使能输出并回到 90° | `OK servo=center angle=90` |
| `servo <60-120>` | 渐进运动到指定角度 | `OK servo=target angle=75` |
| `servo status` | 查询状态、角度、目标、脉宽、输出和限位 | `SERVO state=idle ready=1 angle=90 target=90 pulse_us=1500 output=on pin=4 frequency_hz=50 min=60 max=120 speed_dps=60` |
| `servo stop` | 取消调度并关闭 PWM 脉冲 | `OK servo=stopped output=off` |

错误回复：

- `ERR servo_usage; use help`：空参数、非数字、负数、多余参数或超出可解析范围。
- `ERR servo_range min=60 max=120`：角度可解析但不在软件限位内。
- `ERR servo_not_ready`：LEDC 初始化失败。

`help` 已加入 `servo <60-120> | servo center | servo status | servo stop`。原 RGB、I²C、OLED 和眼睛命令保持不变；`status` 仍表示 RGB 状态，不表示舵机位置。

### 6.1 首次烧录发现的问题

首版使用 16 位 LEDC 分辨率，启动时报：


## 10. 已解决问题

- **ESP32-S3 LEDC 最大 14 位**：首版按经典 ESP32 使用 16 位，`ledcSetup()` 返回 0、`ready=0`。改为 14 位后 50Hz 初始化成功；脉宽分辨率约 1.2µs，足以覆盖 SG90。
- **停止后恢复的跳变风险**：`stop` 保留最后已知角度，重新使能时先输出该角度再渐进到目标，而不是直接回到中位；避免停止位置与新目标之间出现额外的大幅跳变。
- **上电自动运动**：`begin()` 写 0 占空比，只有显式命令才使能 PWM；烧录和上电阶段不会自动扫动。
- **首次 `servo center` 看似无反应**：舵机原本已停在 90° 附近时，中位命令不会产生可见位移，容易被误判为故障。验收时应先发一个明显偏离当前位置的角度（如 `servo 105`）确认运动链路，而不是只发 `center`。
- **串口 ACL 与重新枚举**：USB 重新插拔后 `/dev/ttyACM1` 一度消失，ACL 失效；用户重新连接板卡并对当前设备重新设置 `user:hy:rw-` 后烧录成功。这是环境权限问题，不是固件问题。

## 12. 学习要点

- **PWM 参数**：50Hz 对应 20ms 周期；SG90 用 0.5–2.5ms 脉宽表示角度。占空比分辨率越高，脉宽越细，但 ESP32-S3 LEDC 上限是 14 位，选参数前要核对芯片能力。
- **舵机供电**：舵机电流远大于 GPIO 和 3V3 能提供的电流，必须用外部 5V、共地，信号只接 GPIO；不要把电机电源接到开发板电源轨。
- **非阻塞渐进运动**：用 `millis()` 每 20ms 走 1.2°，既让运动可见、可停止，又不阻塞 OLED 和串口；一次 `loop()` 只做一小步。
- **安全停止**：`servo stop` 选择关闭脉冲让舵机放松，而不是持续保持力矩；代价是失去位置保持，重新使能前要知道最后角度。
- **验收用“可见位移”判断链路**：`center` 对已在中位的舵机是无位移命令；验证供电和信号应选一个偏离当前角度的目标，再结合保持力矩或转动方向判断。
- **验证边界**：串口状态、脉宽计算和状态机可以自动验证，但“舵机是否真的转到 75°、是否平滑、是否发热”必须由人上电观察。
